# Эксперимент 001: RL-обучение оркестратора с субагентами

## Гипотеза

Обучение оркестратора Qwen3.5-2B через Agent Lightning и verl, где он вызывает пул замороженных субагентов
(`small`, `medium`, `large` = ministral-3b, qwen-2.5-7b, qwen3.5-9b через OpenRouter) при фиксированных токенных лимитах на задачу,
повышает точность на held-out сплите `val_test` (BrowseComp-Plus, строки 600–799) относительно необученной базы.

Ожидаемый знак эффекта положительный. Если разница внутри доверительного интервала, гипотеза не подтверждена.
Это тоже результат.

## Что фиксировано и что меняется

| Фиксировано (одинаково у базы и обученной модели) | Меняется (одна переменная) |
|---|---|
| `[limits]`: 8192 токена оркестратора на задачу, 2048 на ход, 4096 на субагента, 32768 суммарно, 15 ходов, 8 параллельных субагентов | веса оркестратора: база (`Qwen/Qwen3.5-2B`) против чекпоинта после обучения |
| `[subagents]`: пул `small` / `medium` / `large`, роли, температура 0, `return_max_chars` | |
| `[judge]` и `[retrieval]`: тот же судья и тот же индекс (`qwen3-embedding-8b, эмбеддинги запроса через OpenRouter`) | |
| `[reward]`: `lambda_parallel = 0.1`, `lambda_finish = 0.05`, линейный отжиг за 7 шагов | |
| `[training]` (только при обучении): `lr = 5e-6`, `rollout_n = 4`, батч 16, 100 шагов | |
| Сплит оценки `val_test` (строки 600–799) и код оценки | |

Значения задаёт `experiments/template/config.toml` поверх `configs/base.toml`. Настройки `[training]`
относятся только к обучению, но полный конфиг записывается в каждый прогон: `eval/config.json` при оценке,
`config.resolved.json` при обучении, поэтому различия видны в файлах.

## Как запустить

Команды и порядок шагов: быстрый старт в `README.md`. Для этого эксперимента:

- базовая оценка: `bash scripts/eval.sh experiments/template/config.toml base val_test base`;
- обучение: `bash scripts/train.sh experiments/template/config.toml --run-id run1`;
- оценка чекпоинта после обучения: `bash scripts/eval.sh experiments/template/config.toml <checkpoint_dir> val_test run1-final`,
  где `<checkpoint_dir>` — папка шага `artifacts/checkpoints/template/run1/global_step_N`.

Базовую оценку делайте до обучения: без неё нечего сравнивать. Оценка с тем же RUN_ID и другим конфигом
отклоняется (`eval/config.json` пишется один раз); прерванная оценка продолжается с тем же RUN_ID. Существующую
run-папку обучения `train` не использует: он отказывается (`run directory already exists`), выберите новый `--run-id`.

## Правила проведения

- Конфиг эксперимента не меняется после старта прогона. Новая версия — новый каталог `experiments/NNN_…/`.
- `val_test` — held-out. Если настройка выбрана по `val_test`, это пишется в отчёте.
- Оценка `train` допустима только для диагностики обучения (например, на переобучение). В отчёт она не идёт.
- `val_full` содержит train и никогда не отчитывается как held-out (AGENTS.md, правило 6).
- Сравнение `compare` выполняется только при одинаковом наборе успешно оценённых ID (см. `docs/code_walkthrough.md`).

## Результаты

Заполняется после прогонов. Числа берутся из `orchestrator-research report` и `compare` на `val_test`.
Колонки совпадают с таблицей, которую печатает `report` (`format_report`): `acc` — точность по оценённым вопросам;
`judge_err` — число судейских сбоев (не доля); `orch_tok` — средние токены оркестратора на эпизод;
`sub fin/made` — завершённые и созданные субагенты всего; `stop_reasons` — причины остановки (исчерпание бюджета видно там).

|---|---|---|---|---|---|---|
| База `Qwen/Qwen3.5-2B` | — | — | — | — | — | `base` |
| После обучения, шаг 100 | — | — | — | — | — | `run1-final` |

Парное сравнение (`compare`): разница точности, 95% bootstrap-интервал, McNemar p (двусторонний), число

Статус эксперимента в `experiments/registry.md`: `scaffold` до первого результата.

## Ограничения

- Субагенты и судья — API-модели, их версии меняются у провайдера. Перед публикацией закрепите ревизии
  `benchmark.revision`, `retrieval.index_revision` и `retrieval.corpus_revision` (сейчас `main`).
- Пик памяти ~27 ГБ не измерен; см. `docs/deployment.md`.
- Парсер инструментов `qwen3_coder` и версия vLLM 0.22.0 зафиксированы решением ADR 0005; проверка и
  ограничения описаны в `docs/deployment.md`.
