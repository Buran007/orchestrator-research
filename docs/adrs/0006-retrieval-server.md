# ADR 0006: Поиск как общий HTTP-сервис

Статус: принято, 2026-10-11.

## Контекст
Agent Lightning запускает отдельный Python-процесс на каждый роллаут (до 64 параллельно).
Раньше каждый процесс роллаута загружал FAISS-шарды, корпус и токенизатор (через `assembly.build_retriever`).
Теперь `assembly.build_retriever` создаёт только HTTP-клиент `HttpRetriever`.
При такой параллельности это недопустимо по памяти и времени (минуты и несколько ГБ на процесс).

## Решение
Поиск выполняет отдельный процесс `adapters/retrieval_server.py` (паттерн Search-R1):

| Что | Где |
|---|---|
| Загрузка индекса, корпуса, токенизатора сниппетов — один раз; возвращает `(search, stats)` | `retrieval_server.load_backend(cfg)` |
| HTTP-сервер (`ThreadingHTTPServer`, stdlib); поиск и статистика подставляются аргументами | `retrieval_server.make_server(search, stats, host, port)` |
| Клиент с таймаутом и повторами (сеть, 429, 5xx; 4xx не повторяются) | `adapters/retrieval.HttpRetriever` |
| Повторы запросов к серверу эмбеддингов | `adapters/retrieval.OpenAICompatibleEmbedder`: повторы делает OpenAI SDK (`max_retries` из `[embedding]`) |
| Адрес и параметры повторов | `[retrieval] server_url, timeout_seconds, max_retries` |

Контракт: `GET /healthz` → `{status, documents, vectors}`; `POST /search` `{query, top_k}` → `{results: [{doc_id, text, score}]}`.
`top_k` ограничивается диапазоном 1..50. Сервер отвечает 503 на временный сбой бэкенда (клиент повторяет),
400 на неверное тело и 500 на непредвиденную ошибку.

## Следствия
- Модуль `assembly` не импортирует FAISS, корпус и токенизатор. Загрузка выполняется только в `retrieval_server`.
- Сбой поиска после исчерпания повторов попадает в наблюдение оркестратора с `infra_error=True`
  (`tools.run_search`). Это `infra_errors` эпизода, поэтому вопрос перезапускается при resume. Поиск субагента
  при таком сбое возвращает текст ошибки в сообщение модели субагента, и `SubagentRun.infra_failure` не ставится.
  Эту границу нужно учитывать при анализе.
- Потокобезопасность: `faiss.IndexFlatIP.search` только читает индекс, поэтому блокировки нет.
  Эмбеддинг-запросы идут параллельно потоками сервера, поскольку именно они медленные.
- Сервер нужно поднять до запуска обучения и оценки. `doctor` проверяет `/healthz` и выводит подсказку.
